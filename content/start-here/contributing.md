Every change goes through review before it is published.

## Request a change (no GitHub needed)

1. In the IT Slack channel, run `/wiki-change`.
2. Fill in the form: which page, what is wrong, what it should say, urgency, photos.
3. A GitHub issue is created. A draft change is prepared from it.
4. An IT team member reviews the draft and merges or replies.
5. The bot posts in the channel when the change is live.

## Make a change directly (GitHub users)

1. Open a pull request against `main`. One topic per pull request.
2. Keep the page's frontmatter valid. The build fails if a required field is missing. See [Conventions](/start-here/conventions/).
3. Check the preview link on your pull request.
4. Wait for review. Policy pages also need approval from their owner.

## Urgent changes

If a service is down or a page gives unsafe or wrong instructions, mark the request **Urgent**. An IT lead can fast-track review.
